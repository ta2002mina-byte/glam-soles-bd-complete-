# Glam Soles BD — Phase 8

Phase 8 adds Order Tracking and the full authenticated Customer Account area
on top of the Phase 7 COD checkout.

## Included

- **Auth (minimal, email/password only — phone/OTP and social login left
  for a later phase as the master spec marks them optional):**
  `app/actions/auth.ts` — sign up, sign in, sign out, password reset
  request. `components/account/account-auth-gate.tsx` renders sign-in /
  create-account / forgot-password directly at `/account` when signed out.

- **`/account`** — layout (`app/account/layout.tsx`) gates the whole area:
  signed-out visitors see the auth gate, signed-in customers get the
  sidebar/tabs nav (`components/account/account-nav.tsx`) plus:
  - **Profile** (`/account`) — name/phone edit, membership tier, points,
    member-since date.
  - **My Orders** (`/account/orders`, `/account/orders/[id]`) — order list
    and a detail page with the same status timeline used by public
    tracking.
  - **Wishlist** (`/account/wishlist`) — redirects to the existing
    Phase 6 `/wishlist` page rather than duplicating that logic.
  - **Rewards** (`/account/rewards`) — real tier, points balance and
    points history from `reward_transactions`.
  - **Addresses** (`/account/addresses`) — add/edit/delete/set default,
    label Home/Office/Other.
  - **Returns & Exchanges** (`/account/returns`) — request a return for
    any delivered, not-yet-requested item (reason, description, optional
    photo to a private bucket); lists prior requests with status.
  - **My Reviews** (`/account/reviews`) — the customer's own reviews with
    approval/verified-purchase state.
  - **Coupons** (`/account/coupons`) — active coupons with real
    eligibility (membership tier, first-order-only) plus redemption
    history.
  - **Notifications** (`/account/notifications`) — real notifications
    generated by order status changes; mark one or all as read.
  - **Settings** (`/account/settings`) — password reset, account status.
  - **Logout** — in the sidebar, calls `signOutAction`.

- **`/track-order`** — public order tracking by order number + phone
  (guests) or order number alone (signed-in owners), plus one-time
  confirmation-token links. Same status timeline component as the account
  order detail page.

## Supabase setup

### 🔴 SUPABASE SQL COMMAND — RUN IN SUPABASE SQL EDITOR

Run this file after migrations `001` through `012`:

```text
supabase/migrations/013_phase8_account_order_tracking.sql
```

It adds:

- `orders.courier_name`, `orders.tracking_number` (nullable; set by staff
  in the Phase 9 admin panel).
- A private `returns` storage bucket + owner/staff policies for
  return-request photos (object path convention `<user_id>/<file>`, same
  as the existing `reviews` bucket).
- `notify_order_status_change()` trigger — writes a real `notifications`
  row whenever a signed-in customer's order is inserted or its status
  changes, so the Notifications section has genuine data instead of
  placeholders.
- A partial unique index so an order item can only have one *active*
  (non-rejected) return request at a time — defence in depth alongside
  the eligibility checks in the app.
- `track_order(p_order_number, p_phone, p_confirmation_token)` RPC — the
  only way `/track-order` reads order data; it never exposes another
  customer's order (checked server-side against `auth.uid()`, the
  checkout confirmation token, or the guest phone number).

`next.config.ts` was updated to allow `next/image` to load signed URLs
from the private `returns` bucket (`/storage/v1/object/sign/**`), in
addition to the existing public-bucket pattern.

## Verification

- This sandbox has no network access, so `npm install` could not
  complete here and `npm run typecheck` / `lint` / `build` could not be
  executed. Everything above was written and then manually re-checked
  against the existing codebase's conventions: type exports resolved,
  Supabase select/embed shapes matched against the actual migrated
  schema, RLS policies re-read against every new query and action, and
  Next.js 15/16 async `params`/`searchParams` conventions followed.
- **Please run `npm run typecheck && npm run lint && npm run build`
  yourself before deploying** — that's the one check this environment
  genuinely couldn't perform.

## Manual test path

1. Apply migration `013` (after confirming `001`–`012` are already
   applied).
2. Visit `/account` signed out → create an account → confirm the
   Profile section loads with real (empty) data.
3. Place a COD order while signed in (Phase 7 checkout) → confirm it
   appears in `/account/orders`, and a "Order confirmed" notification
   appears in `/account/notifications`.
4. Open the order detail page and confirm the timeline matches the
   order's real `status`.
5. Visit `/track-order` signed out, search using the order number + the
   phone used at checkout → confirm the same order appears; try a wrong
   phone number → confirm "We couldn't find an order with those
   details."
6. Add, edit, delete and set-default a saved address in
   `/account/addresses`.
7. In Supabase, manually set an order's `status` to `delivered`, then in
   `/account/returns` submit a return request with a photo → confirm it
   appears with status "requested" and the item no longer appears as
   eligible.
8. Confirm RLS: while signed in as customer A, try loading customer B's
   `/account/orders/[id]` URL directly → confirm it 404s.
